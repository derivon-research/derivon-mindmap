# PROTOTYPE · 大图的进入 / 定向 / 阅读

**一次性代码，不进 main，不要在它上面继续开发。** 它只回答一个问题：

> 打开一张 293 个概念的图，用户从哪里开始？

三处已知断裂：大图布局给不出入口；求解路线要求手动指定起点与目标，而用户两个输入都提供不了；把图当教材读时必须退出文档才能看下一步。

## 怎么跑

`npm run dev` 后打开 <http://localhost:1420/prototypes/entry-orientation/index.html>。

## 只有定稿 F 进了树

探索过七个变体。**只有 `F` 被提交**，其余六个（现状对照、搜索先行、分区地图、对话先行、融合稿、教学流程）在定稿之后丢弃，不在仓库里。

`F` 是学习侧的定版参照，重写照它做交互与布局：

**三个模式**而不是三块面板：**定向**（对话框兼搜索，保留预设问答，先收目标——**可以多个**——再一轮轮问已知；右侧大图随对话点亮）→ **学习**（教材占主体，左栏 Ask AI 接着定向态的对话位置，右栏路线子图记进度，大图退场）⇄ **浏览**（自由逛，随手点开、设为目标或标记已会）。

中间的教材**推导在前、定义在后**：人是先看见一个问题怎么被解决，才能接受那个定义。定义之后挂一个**拿它去做件事**的理解验证任务（任务由图生成，多半是「下一步为什么非得先有它」），任务交了才解锁下一步；定义未展开时 Agent **不替你说答案**，只给提示与前置。

学习态两侧各有**展开 / 折叠 / 隐藏**三态，展开一侧自动收起另一侧；路线栏默认折叠成线性步骤清单，展开才画子图；回答里出现整行公式或可交互组件时**自动展开**。对话**随建随弃**：不留历史列表，新建就是丢掉旧的开一段新的，目标与进度是应用状态、不受影响。确认目标之前先过一屏**路线预览**（步数、成本、领域分布、逐步依据、子图）。「改目标 / 路线学习 / 大图浏览」在**应用顶栏**，不属于任何一个面板。

明确否定的方案：分区导航、把大图当操作对象、卡片粒度地问已知、分段审问式的教学流程（留作扩展口，不进 v1）。

⚠️ **渲染方案不要照抄。** `F` 用 d3-force + 裸 SVG 画图，那是原型的权宜之计。重写只用 G6。这份原型只作交互与布局的参照，不含渲染方案与数据接法。

## 数据是真的，有两处不是

- **图**：`math-reforged` 的真实工作区，293 个概念 / 340 条推导，未删减。
- **文档**：真实的 `document.md`，含 KaTeX 公式与出处引用。
- **路线**：`generate-fixtures.mjs` 用**真实的 derivon CLI** 把「4 个已知集合预设 × 293 个目标」= 1172 条路线全部预先求解好（7.2 秒），所以浏览器里不需要求解器。这些是**精确解**（`provenOptimal`）。
- ⚠️ **自定义已知集合**（B 的按块勾选、C/D 的对话推断、E 的权重改写）不在预设里，用的是 `data.ts` 里一个 Bellman-Ford 松弛的近似解，界面上标为「近似解」。它只是让原型点得动，不代表求解器的真实行为。
- ⚠️ **12 个领域块（tag）是手写的**，见 `generate-fixtures.mjs` 里的 `TAG_RULES`。真实的图**没有 tag 这个字段**。如果 B 赢了，「谁来打这些 tag、要不要进协议」就是一个必须回答的新问题。

重新生成 fixtures（需要 `derivon` CLI 和同级的 `../math-reforged` 克隆）：

```sh
node prototypes/entry-orientation/generate-fixtures.mjs
```

## 不在范围内

- 编辑（建点、连边、替换视图）：这里只有读者视角。
- 教学状态的持久化与回传：另一张票（教学回路与回传动机）。
- 性能：force 布局在这里是同步跑 300 tick 的，真实产品不能这么干。
