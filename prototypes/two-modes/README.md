# PROTOTYPE · 一个应用、两种模式

**一次性代码，不进 main，不要在它上面继续开发。** 它只回答一个问题：

> 打开应用之后，桌面和网页分别看到什么？创作当中「随时进入当前图的学习模式」到底长什么样？

#44 只写了「一个应用、两种模式」和「模式入口属于应用顶栏」，没写清楚第一帧是什么、
切换以后画面怎么变。这份原型把三种答案画出来，供挑一个。

## 结论：A 胜出

**定版是 A（整窗切换）**，已写回 #44 的正文。B（停靠预览）与 C（视图标签）被否掉，留在这个
分支里作对照，不进 main。

A 赢在两点：桌面与网页是同一个形态（web 只是把段控拿掉），以及懒加载边界最好切——两个模式
是互斥子树，创作首屏不会被学习侧的公式排版拖累。B 的停靠让两侧常驻，首屏预算说不清；C 把
「模式」偷换成「视图」，多一层窗口概念，还要求 #44 重写措辞。

已经定死、三个变体都不再摇摆的两条：

- **不做模式选择屏**。没有「学习模式 / 创作模式」两个大按钮的欢迎页。
- **网页端 = 定稿 F 原样**。没有工作区选择，只有唯一那张官方图，打开即定向态；
  创作侧在 web 构建里不存在，所以顶栏里也没有它的入口。三个变体的网页端渲染的是
  **真实的 `../entry-orientation/variants/Final`**，不是仿制品。

## 怎么跑

`npm run dev` 后打开 <http://localhost:1420/prototypes/two-modes/index.html>。

底部悬浮条：`←` / `→`（键盘方向键同样）切变体，`桌面 / 网页` 切宿主，`↺` 回到冷启动第一帧。
状态写进 URL：`?variant=A|B|C&host=desktop|web`，可以直接把某一格发给别人。

> 数据取自 `../entry-orientation/fixtures`，那份 fixtures **不在 git 里**。先在那个原型目录跑
> `node prototypes/entry-orientation/generate-fixtures.mjs`（需要 `derivon` CLI 与同级的
> `../math-reforged` 克隆），否则这份原型起不来。

## 三个变体

差别不在配色，在**窗口由什么构成**，以及**进入学习时创作发生了什么**。

### A · 整窗切换

顶栏一个 `[创作 | 学习]` 段控，一次只在一个模式里。冷启动第一帧是整窗的**最近工作区列表**。
点「学习」，整窗换成学习侧，**带走你在创作里选中的那个概念**当目标，已知取工作区的默认路线
种子；顶栏后半段换成 F 自己的三个学习内模式。点「创作」原样退回。

心智最简单，和 web 端形态最接近（web 就是把段控拿掉）。代价：看不到对照，改一句文档要
来回切一次。

### B · 停靠预览

不离开画布。顶栏右侧一个 `[关 | 停靠 | 全屏]` 的**学习视角**开关，停靠时右边一栏就是学习者看到的
东西，**跟随画布选中的概念**实时变。冷启动没有启动屏，直接是上次的工作区、创作态。

「随时进入」最字面的一种：创作即所见即学，改完权重马上看见路线怎么动。代价：停靠一栏塞不下
F 的定向对话，抽屉里只有「以当前概念为目标的路线 + 教材」；真的要定向还得按全屏。

### C · 视图标签

窗口装的是**视图**：创作是一个标签，每次在检查器里点「以此为目标学习」开一个学习标签，可以同时
存在多个（不同目标），可以并排分屏。冷启动第一帧是一个「起始页」标签，打开工作区后它就地变成
创作标签。web 的标签条只装得下学习视图，所以那里根本不画标签条。

唯一支持「一边改图一边核对两条不同路线」的形态。代价：多一层窗口概念，标签是新的心智负担，
而且它把「模式」偷偷变成了「视图」——两种模式的说法要跟着改。

## 没有回答、挑完之后必须回答的

1. **桌面进入学习，目标从哪来？** 三个变体都假定「当前选中的概念就是目标」，并用工作区的默认
   路线种子（#57）当已知，跳过整个定向问答。如果作者想换一组已知，是回到 F 的定向态，还是
   借 #58 的定向预览？
2. **创作中的图经常是半成品。** 目标不可达时学习模式要给什么，原型里没有画。#47 的路线预览
   得有一个「无解」态，而且在创作里会是常态，不是异常。
3. **懒加载边界怎么切。** A 的整窗切换最好切（两棵子树互斥）；B 的停靠让学习侧的教材渲染常驻在
   创作首屏旁边，得确认它不把公式排版拖进创作的首屏预算；C 介于两者之间。
4. **C 若胜出，#44 的措辞要改**：「两种模式」变成「一个窗口、多个视图」，AC 里「模式切换的入口
   属于应用顶栏」要重写成标签条的说法。
