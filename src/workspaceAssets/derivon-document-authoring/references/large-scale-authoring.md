# Large-scale document authoring

Use this workflow only after the user explicitly requests polished or expanded
documents across more than five objects, more than one chapter, or a substantial
graph region. It is not the workflow for importing sources or populating graph
placeholders.

The protocol names capabilities, not vendor APIs. A platform may call them
SubAgents, child agents, delegated tasks, parallel agents, workers, or something
else. Detect what the environment actually provides.

## Capability gate

When SubAgents or equivalent delegation are available, actively use them. Give
each writer a bounded, non-overlapping document cluster with its graph neighbors,
authoritative sources, subject-specific acceptance criteria, and exact file
ownership. Use a separate reviewer when capacity permits.

Delegated writers may edit directly when isolated worktrees or exclusive disjoint
paths are guaranteed. Otherwise they return drafts or patches and the main Agent
integrates them. Never allow multiple Agents to edit the same file.

When delegation is unavailable, tell the user before undertaking a large serial
rewrite. Offer a bounded sequential batch or ask them to use an environment with
SubAgent support; do not silently turn the request into hours of single-context
work. Capability changes scheduling, not document standards.

## Freeze scope and standards

Inventory the requested pages once and classify them as accepted exemplar,
provisional draft, or missing. Freeze the page list, sources, audience, and
acceptance criteria before dispatch. Use subject-authoring Skills to define
domain-specific quality; do not invent a stricter standard during review.

Keep one compact main-Agent ledger with cluster, status, blocking finding,
publication state, and audit result. It is coordination metadata, not another
source of lesson prose.

Scripts may inventory, render, compare, and audit. They must not contain lesson
prose, chapter-sized text maps, or templates that bulk-author documents. Existing
content generators may be inspected as provenance but must not be extended or
treated as evidence of quality.

## Form work units

Group documents by a coherent reader problem and their local graph neighborhood,
not by arbitrary path order or equal file counts. Keep tightly coupled points and
hyperedges together so terminology, sources, and examples remain consistent.

A writing assignment states:

- exact objects and files;
- required neighboring objects;
- authoritative sources and accepted exemplars;
- reader assumptions and subject-specific standards;
- whether interaction is expected or left to the writer's judgment;
- allowed output location and the prohibition on unrelated shared-file edits.

Ask for complete documents, not outlines awaiting another generic expansion
pass. Do not create separate research stages when a bounded writer can read the
supplied source and write the cluster directly.

## Bound review and repair

The first batch contains one representative pilot cluster. After it passes, use
available parallel capacity for disjoint clusters.

Classify review findings:

- **Blocking:** factual or inferential error, material source conflict, missing
  applicable acceptance element, graph-role mismatch, or broken publication,
  accessibility, or interaction.
- **Non-blocking:** optional analogy, extra example, alternative presentation,
  stylistic preference, or polish beyond the frozen standard.

Each cluster receives one review pass and at most one repair pass for blocking
findings. Verification checks only those findings; it does not restart the
review. If a blocker remains, mark the object blocked with the exact reason and
continue unaffected work. Non-blocking ideas never delay acceptance.

An accepted page is closed. Reopen it only for concrete new evidence of a
blocking defect or a changed user requirement, not because further improvement
is imaginable.

## Integrate and finish

The main Agent reconciles shared terminology, integrates accepted changes,
publishes `index.html`, and audits changed pages. Run graph-wide validation once
at the end unless an actual structural error requires an earlier check.

Finish when every frozen page is accepted or explicitly blocked, accepted pages
are synchronized and audited, and workspace validation passes. Report blocked
objects and their concrete reasons. Do not restart inventory, expand scope, or
continue looking for optional improvements after this checklist passes.
