## 界面：三个变体各自的取舍

| | 创作侧 | 学习侧 | 主要操作 | 代价 |
| --- | --- | --- | --- | --- |
| **A · 工作台视图** | 第四个中心视图「路线」，与对象、图浏览、开局并列；左栏是路线列表，中间是步骤表，右边是路线子图 | 路线书架分两组：「这个工作区带的」（只读）和「我的」；「另存为我的路线并修改」后用同一张步骤表编辑 | 在表里逐步改 | 导航多一项；步骤表看不出图的形状，要看右边的子图 |
| **B · 图上编辑** | 不加新视图。图浏览多一个「路线图层」下拉，选中一条路线就在图上编辑：点一个点可以换平行推导或去掉这一步；缺的概念画成红色虚框，点它可以补上；底部一条顺序带，可以拖动 | 路线页顶部一个下拉，分组列出全部路线；「改成我的路线」后在同一张图上编辑 | 在图上点 | 路线长时图很宽；顺序与图分开显示，看顺序要看底部那条 |

## 存储与 schema：三种方案

| | 工作区路线 | 个人路线 | schema |
| --- | --- | --- | --- |
| **1 · 两处两协议**（#153 草案） | `.derivon/routes/<id>.json`，`derivon.workspace-routes/v1` | 仍放在应用数据目录的 `routes.json`，`derivon.routes/v1` | `derivationIds` 加可选的 `order` |
| **2 · 一协议两处** | `.derivon/routes/<id>.json` | `<应用数据目录>/learner-records/<工作区 id>/routes/<id>.json` | 同一个 `derivon.route/v1`：`steps` 加 `ordered`；个人路线多一个 `basis`，另存来的多一个 `basedOn` |
| **3 · 两处各一个文件** | `.derivon/routes.json`（路线集） | `routes.json` 放宽成与工作区同形 | `derivationIds` 加可选的 `order` |

## 走查中发现的问题（只是原型的读数，还不是结论）

- **个人路线放不进现在的 `derivon.routes/v1`。** 这个协议要求 `order`、`cost`、`basis`，名字只有一个
  `description`，也没有地方放 `basedOn`。方案 1 只能把个人路线存成「写定的顺序」，并把 label 和 description
  合成一个字段。三种方案里，**只要学习者能自己编路线，就得改一个已经落地的协议**：方案 2 把 `routes.json`
  拆成目录，方案 3 放宽它的字段。
- **`derivationIds` 和 `order` 会把同一批 id 存两份。** 方案 1 和方案 3 里，写了顺序的路线把同一批 id 存两遍，
  而且两份必须保持一致。方案 2 用 `steps` 加 `ordered: true/false` 表达同一件事，只存一份。
- **一处缺口会连带报出一大串错误。** 删掉「向量空间」那一步，最初一共报出 1 个错误和 6 条提示。现在只报根因：
  哪个目标到不了、缺哪个概念、哪条推导能补上；其余受牵连的步骤合成一句「另有 12 步因此暂时走不了」。
  一条推导不通往任何目标时的「绕路」提示，在目标还到不了时也不再显示。
- **把一步挪到前提之前，会报出好几条错误，而它们是同一个原因。** 例如「第 2 步『子空间』要用『向量空间』，
  它在第 5 步才得到」一共报出 3 条。可以考虑合并成一条建议：「把『向量空间』挪到第 2 步之前」。
- **拖动任何一步都会让顺序变成「写定」。** 这个状态变化不说出来，作者就看不见，所以编辑器在顺序旁边显示
  「现算 / 已写定」，并提供「改回现算」。
- **补上的推导插在它最早能走的位置**，不追加到末尾。否则「补上」这个动作本身又会造出一个顺序错误。
- **「另存为我的」得到的是一份拷贝，不是链接。** 作者之后改了原路线，学习者的这份不会跟着变。
  `basedOn` 只记录这份拷贝从哪条路线来。
- **C 的学习侧只列出真能走到当前目标的路线。** 走向别的目标的路线单独写一行，
  不假装它们也能走到奇异值分解。
